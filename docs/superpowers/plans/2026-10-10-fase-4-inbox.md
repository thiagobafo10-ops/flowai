# FlowAI — Fase 4: Inbox + Conversas + Mensagens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Inbox funcional em três colunas com tempo real, canal Simulador para receber/responder mensagens de ponta a ponta, e a porta única de entrada `ingest_inbound_message` que a Fase 5 reutiliza.

**Architecture:** Entrada por função SQL `SECURITY DEFINER` transacional; saída por Server Action + `ChannelProvider` (`@flowai/core`); leitura em Server Components + React Query; tempo real com Supabase Realtime `postgres_changes` (RLS) atualizando o cache. Mensagens de sistema e "marcar como lida" por funções definer com checagem de papel.

**Tech Stack:** Next.js 16.4 (`cacheComponents`), React 19, Tailwind 4, shadcn/ui base-nova, React Hook Form + Zod 4, `@tanstack/react-query`, `@supabase/supabase-js` Realtime, Supabase local (Postgres 17), pgTAP, Vitest, Playwright (build de produção, porta 3100).

**Spec:** `docs/superpowers/specs/2026-10-10-fase-4-inbox-design.md`

## Review Focus

1. **Mesmo `external_id` entregue duas vezes** (webhook repetido) → uma única mensagem, sem efeitos duplicados. Teste na Task 3.
2. **Telefone do remetente em formatos diferentes** (`(11) 99999-8888` vs `+55 11 99999-8888`) → mesmo contato e mesma conversa. Testes nas Tasks 1 e 3.
3. **Dois agentes clicando "Assumir" na mesma conversa quase ao mesmo tempo** → o último vence, ambos veem o estado final sem recarregar, nenhum erro. Teste na Task 8.
4. **Mensagem só com espaços ou acima de 4096 caracteres** → recusada com mensagem clara; exatamente 4096 aceita. Testes nas Tasks 1 e 6.
5. **`/inbox?c=<id de conversa de outra organização>`** → abre o Inbox normalmente sem conversa selecionada, sem vazar dados. Teste na Task 7.
