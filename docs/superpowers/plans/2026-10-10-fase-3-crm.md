# FlowAI — Fase 3: Contatos + Tags + Pipeline + Deals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Módulos Contatos e Pipeline funcionais (CRUD de contatos com tags e campos, kanban de deals com arrastar e soltar), gerenciamento de Tags e editor de etapas em Configurações.

**Architecture:** Leitura em Server Components (filtros na URL); gravação por Server Actions (Zod + `getActiveOrg` + papel; RLS como segunda barreira); kanban com React Query + dnd-kit e atualização otimista. Operações de várias linhas em funções SQL transacionais. Lógica pura (schemas, telefone, filtros, totais) em `@flowai/core`.

**Tech Stack:** Next.js 16.4 (`cacheComponents`), React 19, Tailwind 4, shadcn/ui base-nova (`@base-ui/react`), React Hook Form + Zod 4, `@tanstack/react-query`, `@dnd-kit/core` + `@dnd-kit/sortable`, Supabase local (Postgres 17), pgTAP, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-09-fase-3-crm-design.md`

## Global Constraints

- Branch `feat/fase-3-crm`. Nunca editar migrations existentes; novas com prefixo `20261010`.
- Textos de UI pt-BR exatamente como na spec. Nenhum dado fictício; estados vazios explícitos.
- Toda página de `(app)` envolve o conteúdo em `RequireOrg` (`apps/web/src/components/require-org.tsx`); toda Server Action chama `getActiveOrg()` e confere o papel (`viewer < agent < admin < owner`) antes de gravar.
- Service role nunca em `apps/web`. Nunca `select *` em `channels`.
- Leituras dinâmicas dentro de `<Suspense>` (Next 16 `cacheComponents`); `searchParams`/`params` são Promises.
- Funções `SECURITY DEFINER`: `set search_path = ''`, nomes qualificados, `revoke ... from public, anon`, checagem explícita de papel com `public.has_role`. Os testes globais 009 devem continuar passando.
- Rótulos: status `lead`→"Lead", `customer`→"Cliente", `inactive`→"Inativo"; origem `whatsapp`→"WhatsApp", `instagram`→"Instagram", `manual`→"Manual". Moeda sempre BRL.
- Mensagens fixas: "Você não tem permissão para esta ação."; "Não foi possível concluir. Tente novamente."; "Este contato já tem um deal aberto."; "Já existe uma tag com este nome.".
- Docker: em todo comando que usa `docker`/`supabase`, prefixar `export PATH="/c/Users/thiag/AppData/Local/Programs/DockerDesktop/resources/bin:$PATH"`. Após `npm run db:reset`, aguardar os containers ficarem saudáveis antes do e2e.
- Verificação web: `npm run typecheck`, `npm run lint -w apps/web`, `npm run build -w apps/web`, `npm run e2e -w apps/web` (em primeiro plano). Banco: `npm run db:reset; npm run db:test`; após mudar schema/funções, `npm run db:types`.
- Commits terminam com a linha `Co-Authored-By` da atribuição da própria sessão.

## Decisão de implementação (complementa a spec §4.3)

Para garantir os invariantes das etapas (exatamente um Ganho, um Perdido, ≥ 1 aberta) sem quebrar pipelines de teste das fases anteriores, as funções de etapa são **`SECURITY DEFINER` com checagem `has_role(org, 'admin')`**, e a escrita direta de `authenticated` em `pipeline_stages` fica restrita a `update (name)` (insert, delete e update de `position/is_won/is_lost` revogados). A spec §4.3 será atualizada para refletir isso (Task 3).

## Review Focus

1. **Mesmo telefone digitado em formatos diferentes** (`(11) 99999-8888`, `11999998888`, `+55 11 99999-8888`) → normalizado igual e o aviso de duplicidade aparece. Testes nas Tasks 1 e 4.
2. **Busca sem acento** (`joao`) encontra "João"; e por parte do telefone (`99998888`). Teste na Task 2.
3. **Deal excluído por outra pessoa enquanto é arrastado** → toast de erro, card volta e o quadro se atualiza sem o deal. Teste na Task 7.
4. **Contato sem nome** (só telefone ou e-mail) → em lista, ficha e card do kanban aparece o telefone ou e-mail no lugar do nome. Testes nas Tasks 1 (função `contactDisplayName`) e 4.
5. **Filtro de tag na URL apontando para tag excluída** → lista abre normalmente, ignorando o filtro inválido. Teste na Task 6.
